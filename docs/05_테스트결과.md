# 테스트 결과

## 진행 상태

- 현재 대상: `docs/04_개발계획.md`의 다음 미완료 항목인 **EPIC 1. 안전한 사용 및 가상 기준자료 기반**.
- 상태: **미완료**. 실제 Supabase 프로젝트/점주 OTP 계정·데이터베이스가 준비되지 않았고, Next.js 의존성 설치가 npm 레지스트리 연결 오류로 끝나 실행 앱을 구동하지 못했다. 사용자의 화면 확인도 아직 받지 않았다.
- 완료 판정 원칙: 아래 확인 항목을 사용자가 화면에서 확인했다고 알려주기 전까지 개발 계획에서 완료로 표시하지 않는다.
- 배포 및 GitHub 업로드: 수행하지 않았다.

## 구현 내용

- Next.js App Router, Supabase 이메일 OTP, 서버 측 점주 이메일 허용 확인 및 세션 확인 코드를 추가했다.
- 메뉴·재료·레시피 기준자료 전용 표와 사용자별 RLS(데이터베이스 행 접근 제한) 마이그레이션을 추가했다. 로그인된 점주의 첫 방문에서 가상 기준자료를 멱등 저장(반복 실행해도 중복되지 않음)하고, 기존 자료 수가 다르면 자동 덮어쓰지 않도록 했다.
- Supabase 환경 설정이 없을 때 인증을 사용할 수 없다고 알리는 로그인 UI 상태를 구현했다.
- npm 패키지는 레지스트리 접속 오류(`ECONNREFUSED`)로 내려받지 못했다. 앱 런타임, 타입 검사, 실제 Supabase Auth/RLS/DB 저장 확인은 실행하지 못했다.
- 데이터 검증용 스크립트와 독립 실행형 `index.html` 인터랙티브 미리보기를 만들었다. 미리보기는 실제 인증이나 저장을 하지 않는다.

## 실행한 검사와 결과

- **통과:** 제공 JSON의 메뉴 8종·재료 11종·레시피 22건, 고유 ID, 레시피의 메뉴/재료 참조, 단위 일치, 양수 사용량을 검사했다.
- **통과(정적 확인만):** 세 기준자료 표 모두 RLS가 활성화되고 `auth.uid()` 소유자 기준 정책이 존재하는지 검사했다. DB가 실제 정책을 적용했는지는 미확인이다.
- **통과(미리보기 한정):** 독립 실행 `index.html`에서 체험 모드 고지, 기준자료 홈, 메뉴/재료 목록과 검색, 레시피 필터를 탐색했다. 데이터가 8/11/22건으로 표시되고 샘플 레시피 연결(예: 아메리카노=원두 20g+포장컵세트 1개)이 맞았다. 이 페이지는 화면 체험용으로 실제 OTP·DB 저장을 하지 않는다.
- **미실행:** Next.js 타입검사/빌드, 실제 이메일 OTP, 허용되지 않은 계정·잘못된 코드 거부, Supabase 마이그레이션/RLS, 가상 기준자료 DB 저장·새로고침/재로그인 조회. 의존성 tarball을 npm 레지스트리에서 받지 못했고 Supabase 환경값이 없다.
- EPIC 1에 해당하지 않는 이후 EPIC 기능은 이번 실행에서 검사하지 않았다.

   - 사용자가 “문제없이 확인”이라고 응답하면 이 화면 확인만 완료로 기록한다. EPIC 전체 완료는 실제 OTP·DB 저장·새로고침/재로그인 확인까지 끝난 뒤에만 표시한다.

## 수정·재검사 및 남은 문제

- 샘플 기준자료 검사 스크립트와 RLS 코드 정적 검사를 추가하고 실행해 통과했다.
- 사용자 화면 확인은 아직 이루어지지 않았다. 앱 자체의 빌드 및 Supabase 연결 검사는 실행 환경 제약으로 미확인이다.
- EPIC 1은 미완료이며, 사용자 확인 전 개발 계획에서 완료로 표시하지 않는다.

## 별도 화면 미리보기 변경

- 요청에 따라 독립 실행형 `index.html`의 가상 업종 예시를 카페에서 족발집으로 바꿨다. 족발·막국수 메뉴 8종, 재료 12종, 레시피 연결 25건은 미리보기만을 위한 임의의 가상 값이며 매장 제공 자료/확정 PRD 내용이 아니다.
- 메뉴·재료·레시피 화면 전환 및 메뉴 검색을 로컬 브라우저에서 확인했다. 이 화면 체험은 OTP 로그인, 실제 DB 저장·복원 또는 계산을 수행하지 않는다.
- 이 화면 변경은 카페 범위의 EPIC 1 구현·검사 결과와 별개다. 실제 서비스 문서와 업무 앱의 업종 전환은 이번 미리보기 요청 범위에 포함하지 않았다.

## 추가 미리보기 탭 — 매출분석·커뮤니티

- 사용자가 요청해 족발집 독립 미리보기에 두 탭을 추가했다. 예시 판매가는 메뉴 기준 판매가이며 비용·원가를 계산한 손익은 아니다.
- **매출분석 AI 브라우저 검사:** 2026-09-27 하루 샘플의 매출은 1,048,000원, 판매 수량은 44개, 상위 메뉴 족발 대 매출은 294,000원이다. 9/21~9/27 주간 매출은 6,604,000원, 판매 수량 282개이며 메뉴별 금액 합과 일별 합계가 일치한다. 주문 수가 아니라 판매 수량으로 표시된다.
- **커뮤니티 AI 브라우저 검사:** 매출·메뉴, 재료·재고, 마감·운영 사례 글과 사례 댓글을 열었다. 질문 작성 창에서 가상 글을 추가했을 때 현재 화면 목록에만 나타났다. 글·공감·댓글은 서버에 게시되거나 저장되지 않는다.
- 커뮤니티의 “실제 사용 사례”는 실제 매장이나 점주의 증언을 수집한 것이 아니라, 주말 판매 준비·재고 확인·평일 사이드 판매 검토 같은 현장형 흐름을 바탕으로 쓴 **가상 상황 예시**다.
- 내 확인: 미확인. 브라우저에서 메뉴 선택, 사례 읽기, 질문 작성이 의도대로 보이는지 아직 사용자가 확인하지 않았다.
