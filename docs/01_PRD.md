# 프렙 카페 운영 관리 웹 프로그램 PRD

> 제품 요구사항 문서(PRD)는 서비스가 해결할 문제, 사용자, 기능 범위와 완료 기준을 정리한다. 이 문서는 제공된 자료와 현재까지의 요청을 바탕으로 작성했다. 합의되지 않은 정책은 임의로 확정하지 않고 `미정`으로 표시한다.

## 사용 목적

카페 점주가 매일 판매와 운영 기록을 관리하고, 메뉴별 수익성 및 기간별 손익을 확인하며, 재료 부족 여부를 살펴볼 수 있도록 돕는 웹 프로그램이다.

첫 수업에서는 판매 기록을 입력한 뒤 메뉴 수익성을 확인하고 실제 손익과 재료 잔량까지 이어서 확인하는 핵심 흐름을 구현한다. 수업 중 범위에는 계산 정확성, 기록 저장, 기본 입력 검증과 오류 처리를 포함한다.

## 자료의 종류·기간·단위·중복 주의사항

### 자료에서 확인한 사실

- 자료 출처: 직접 구성한 가상 매장 샘플이며 매장명은 프렙 카페다.
- 기록 기간: 2025-07-01~2026-09-18 마감. 이후 2026년 9월 말까지는 영업 달력 자료만 있다.
- 통화 및 금액 기준: 원화(KRW), 부가세 제외 금액.
- 재료 수량 단위: g·ml·개. 납기와 안전재고 일수는 영업일 기준이다.
- 엑셀과 JSON은 같은 기록을 담은 두 형식이며, 엑셀은 첫 행이 열 이름이고 다음 행부터 기록이다. 둘을 모두 가져오면 같은 자료가 중복될 수 있다.
- JSON의 `meta`에는 출처·기간 등 자료 정보가 있고 `settings`는 비어 있다. 제공 자료만으로 운영 정책이 정해져 있지는 않다.

### 자료에 포함된 기록

| 종류 | 건수 | 내용 |
|---|---:|---|
| 공급사 | 3 | 공급사 ID와 이름 |
| 재료 | 11 | 기준 단위, 구매 용량·가격, 공급사, 납기·안전재고 일수 |
| 메뉴 | 8 | 메뉴, 기준 판매가, 분류, 레시피 버전 |
| 레시피 | 22 | 메뉴 1개당 재료 사용량, 적용 판매 채널 |
| 재료 가격 이력 | 33 | 재료별 적용 시작일, 구매 가격·용량 |
| 영업 달력 | 457 | 영업 여부, 마감 여부, 날씨, 메모 |
| 판매 기록 | 6,112 | 날짜·메뉴·채널별 판매 수량, 단가, 할인, 매출, 비용 관련 값 |
| 초기 재고 | 11 | 시작일 영업 전 재료 수량 |

| 비용 기록 | 3,560 | 날짜별 비용 금액과 구분 |

### 기획 시 주의사항

- 판매 기록은 주문별 내역이 아니라 날짜·메뉴·판매 채널별 집계다. 판매 수량을 주문 건수로 해석하지 않는다.
- 판매 당시 단가·할인·순매출·결제 수수료는 과거 기록값이다. 개당 식재료 원가와 개당 포장 원가는 각각 1개당 값이다.
- 구매 가격은 구매 용량 전체 가격이고, 레시피 사용량은 메뉴 1개를 만들 때 필요한 양이다.
- 레시피의 적용 채널이 비어 있으면 모든 채널에 적용되고, 포장으로 표시된 재료는 포장 판매에만 적용된다.
- 월 비용 계획과 날짜별 비용 기록은 같은 비용을 월·일 단위로 표현한 자료다. 양쪽을 독립 지출처럼 합산하면 중복될 수 있다.
- 공란은 해당 없음 또는 미입력일 수 있으며 숫자 0과 구분해야 한다.
- 미래 날짜의 미마감 판매 기록은 판매량 0과 동일하지 않다.
- 연간 집계는 제공된 일부 기간만 포함하므로 완전한 연간 실적으로 오해하지 않도록 해야 한다.
- 과거 자료에 포함된 원가·수수료·비용 배분값은 앞으로의 수익성 분류, 전망, 비용 배분, 재고 정책을 자동으로 확정하지 않는다.

## 사용자와 사용 순서

### 사용자

- 주 사용자: 매일 마감 업무를 하는 카페 점주.
- 사용 환경: 웹 프로그램. 지원 기기와 계정 방식은 미정이다.

### 수업 중 핵심 사용 순서

1. 해당 영업일의 판매 기록을 입력하거나 기존 기록을 수정·삭제한다.
2. 메뉴별 수익성 결과를 확인한다.
3. 선택한 기간의 실제 손익을 확인한다.
4. 판매에 따른 재료 사용과 보유 기록을 바탕으로 재료 잔량을 확인한다.

위 순서는 요청에서 정한 핵심 흐름이다. 화면 배치와 상세 동작은 이번 문서에서 정하지 않는다.

## 필수 기능

### 수업 중 구현할 범위 — MVP

MVP(최소 기능 제품)는 첫 실습에서 핵심 사용 흐름을 확인할 수 있는 기능 묶음이다. 총 4시간 실습(기획·화면 설계·개발·검사·배포)에 맞춰 다음 범위로 제안한다.

- 판매 기록 직접 입력·수정·삭제
- 메뉴별 수익성 확인
- 실제 손익 확인을 위한 비용 기록 관리(입력·수정·삭제)
- 판매로 인한 재료 사용량과 재고 기록을 반영한 재료 잔량 확인
- 재료 입고·폐기·실제 재고 확인 기록 등 잔량 확인에 필요한 최소 재고 기록
- 일별 및 월별 조회
- 기록 저장 및 다시 열었을 때 저장된 내용 확인
- 잘못되었거나 필수 정보가 빠진 입력에 대한 기본 안내와 잘못된 저장의 방지
- 제공된 자료 예시를 활용한 계산 결과 검증
- MVP 기능을 대상으로 한 기본 검사와 배포까지의 실습 완료

메뉴·재료·레시피 등 분석에 필요한 기준 정보가 앱에 준비되는 방식은 미정이다. 초기 자료를 가져오는 기능을 MVP에 추가할지 또는 실습용 기준 정보를 별도로 준비할지 결정해야 한다.

### 수업 후 확장할 범위

- 엑셀 입력 양식 내려받기와 엑셀 파일 가져오기
- JSON 파일 가져오기
- 데이터 백업 및 복원
- 공급사와 구매 단위를 참고한 발주량 제안
- 예상 손익 및 기간 전망
- 주별·분기별·반기별·연간 조회
- 재고 이력, 입고·폐기·실사 조정 기능 확장
- 추가 자료 관리와 분석 기능

수업 중 MVP와 수업 후 확장 범위는 위와 같이 구분했다. 다만 수업 중 포함할 기능의 정확한 경계는 실습 시간 안에서 조정 가능하며, 조정된 범위는 이후 합의에 따라 갱신한다.

## 제외 기능

현재 PRD 범위에서 다음은 구현 범위로 확정하지 않는다.

- 수업 후 확장으로 분류한 파일 양식·가져오기, 백업·복원, 발주 제안, 예상 손익 및 추가 기간 조회
- 다중 매장, 직원별 권한, 외부 회계·결제·주문 시스템 연동
- 제공 자료에 없는 데이터의 자동 생성 또는 과거 기록의 임의 보정
- 구체적인 계산식, 손익 분류 규칙, 재고 정책, 화면 디자인, 기술 구성 및 세부 상호작용

이 항목들은 자료나 요청에서 합의된 요구가 아니므로, 추가가 필요하면 별도 결정한다.

## 완료 기준

다음은 **수업 중 MVP가 완료되었다고 판단하기 위한 기준**이다. 계산 기준과 검증용 숫자 예시는 관련 미정 사항을 합의한 뒤 정한다.

- 사용자가 판매 기록을 입력하고 수정·삭제할 수 있으며, 변경 내용이 저장되고 다시 열었을 때 확인된다.
- 사용자가 비용 기록을 입력·수정·삭제할 수 있고, 선택한 기간의 실제 손익에 반영된다.
- 사용자가 메뉴별 수익성을 조회할 수 있고 결과가 합의된 정의와 제공 자료의 검증 예시에 맞는다.
- 사용자가 재료 입고·폐기·실제 재고 등 합의된 최소 기록을 관리하고 재료 잔량을 확인할 수 있다.
- 일별 및 월별 조회가 동작하며, 미마감 날짜와 공란을 0으로 잘못 취급하지 않는다.
- 필수 정보 누락, 잘못된 값, 중복 또는 지원하지 않는 입력에서 합의된 기본 오류 안내가 제공되고 잘못된 데이터가 조용히 저장되지 않는다.
- 월 비용 계획과 일별 비용 기록이 중복 합산되지 않는 등 합의된 데이터 해석 기준이 검증된다.
- 기능별 검사 결과와 미확인 항목이 구분되어 기록된다.
- 수업 후 확장 기능은 MVP 완료 여부에 포함하지 않는다.

## 미정 사항

아래 결정은 자료에 명시되어 있지 않거나 사용자가 아직 선택하지 않았다.

- **메뉴 수익성의 의미:** 예를 들어 판매 금액에서 식재료비만 뺄지, 포장비·결제 수수료까지 반영할지. 추천: 사용자가 원하는 메뉴 비교 목적을 먼저 정하고 자료에 있는 값만 사용한다.
- **실제 손익의 항목:** 비용 분류와 비용 인식 기준, 월 비용 계획을 손익 화면에서 어떻게 활용할지. 추천: 실제 손익과 계획 비교를 구분해 중복 집계를 방지한다.
- **예상 손익 기준:** 전망 기간, 가정값, 영업일 처리, 과거 자료 사용 방식. 수업 후 확장으로 두며 별도 합의가 필요하다.
- **재고 잔량 및 발주 참고 기준:** 레시피 버전·가격 적용일, 실사 조정, 납기·안전재고 반영 방식. 잔량 확인에 필요한 최소 범위를 먼저 정하고 발주 제안은 확장 단계에서 결정한다.
- **기준 정보와 초기 자료 준비:** 메뉴·재료·레시피와 기존 기록을 어떤 방식으로 서비스에 준비할지. 파일 가져오기가 수업 후 범위이므로 MVP에서 분석 가능한 데이터를 제공할 대안이 필요하다.
- **가져오기 규칙:** 엑셀과 JSON 중 지원 형식, 하나의 자료를 중복으로 가져올 때의 처리, 잘못된 행·파일 처리 및 기존 자료와의 충돌 해결 방식.
- **저장·백업·복원 기준:** 데이터 보존 위치, 백업 주기·형식, 복원 시 현재 자료와 충돌할 때의 처리. MVP 저장은 완료 기준에 포함하고 파일 백업·복원은 수업 후로 제안한다.
- **기간 조회 우선순위:** MVP에서 일별·월별을 우선하고 나머지 기간은 확장으로 제안했다. 이 순서의 승인 여부.
- **사용자·기기 범위:** 점주 1인 사용인지, 여러 사용자·기기 간 공유가 필요한지.
- **산출물 형식:** 이 문서는 요청에 따라 `docs/01_PRD.md`로 작성한다. 추가 Word(.docx) 문서도 필요한지는 미정이다.
