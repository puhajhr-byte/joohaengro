# 프렙 카페 운영 관리 웹 프로그램 기능 요구사항 (FRD)

> FRD(기능 요구사항 문서)는 사용자의 입력에 프로그램이 어떻게 반응하고, 화면·파일에 어떤 결과를 내야 하는지 정의한다. 이 문서는 `docs/01_PRD.md`와 `디자인/` 폴더의 HTML 시안을 기준으로 한다. 시안에 보이는 메뉴·날짜·금액·상태는 **가상 예시**이며, 현재 실제 계산이나 저장이 구현됐다는 뜻이 아니다.

## 1. 전체 사용 순서

1. 점주는 마감 홈에서 조회 기준일과 당일 상태를 확인한다.
2. 판매 기록을 입력하거나 기존 집계를 검색·수정·삭제한다. 저장 후 날짜·메뉴·채널별 집계와 요약이 갱신된다.
3. 메뉴별 수익성 화면에서 기간·메뉴·채널별 제품 마진을 비교하고, 필요하면 가상 시뮬레이션을 본다.
4. 실제 손익 화면에서 매출·원가·실제 지출을 확인하고, 실제 지출을 추가·수정한다. 월 비용 계획은 별도의 비교값으로 확인한다.
5. 재고 화면에서 판매에 따른 이론 잔량과 입고·폐기·실사 결과를 비교하고, 실제 수량을 기록한다.
6. 확인을 마치면 마감 홈에서 마감 완료를 승인한다. 승인 이후에도 정정할 수 있으며 변경 이력을 남긴다.
7. 수업 후 확장 기능으로 기간 보고서를 파일로 내보내거나 가져오기·백업·복원·발주 참고를 이용한다.

## 2. 기능 목록과 적용 범위

| 기능 | 사용자가 하는 일 | 적용 범위 |
|---|---|---|
| 마감 홈·마감 승인 | 기준일 선택, 진행 상태 확인, 각 관리 화면 이동, 마감 승인 | 수업 중 MVP |
| 판매 기록 | 수기 입력·검색·채널 필터·수정·삭제·일괄 삭제·엑셀 내보내기 | 수기 관리 MVP, 내보내기 수업 후 확장 |
| 메뉴 수익성 | 메뉴·채널별 제품 마진 확인, 원가표 내보내기, 가상 원가 시뮬레이션 | 조회 MVP, 내보내기·시뮬레이션 수업 후 확장 |
| 실제 손익·비용 | 일별·월별 실제 손익 조회, 실제 비용 입력·수정, 월 비용 계획과 비교, 재검산·내보내기 | 핵심 조회·비용 입력 MVP, 예측·내보내기 수업 후 확장 |
| 재료 잔량·재고 | 이론 잔량 확인, 입고·폐기·실사 입력, 잔량 조정, 이력 조회 | 핵심 잔량·최소 기록 MVP, 발주 제안·파일 내보내기 확장 |
| 데이터 준비·가져오기 | 실습용 가상 기준자료 사용, 엑셀 양식·엑셀/JSON 자료 가져오기 | 가상 예시는 MVP, 파일 기능 수업 후 확장 |
| 백업·복원 | 데이터 백업 파일 생성 및 복원 | 수업 후 확장 |

**범위 차이:** PRD는 파일 가져오기, 파일 내보내기, 시뮬레이션, 예측, 발주 제안과 일부 기간 조회를 수업 후 확장으로 두었다. 시안의 일부 화면에는 이 기능의 버튼이 이미 보인다. 따라서 FRD에는 시안 버튼의 동작을 수업 후 확장으로 기록하며, MVP 완료 기준으로 승격하지 않는다. 엑셀/JSON 가져오기와 백업·복원은 PRD에는 있으나 시안에 화면 흐름이 없다. 아래에 기능 요구와 화면 설계 누락을 명시한다.

## 3. 공통 데이터·표시 규칙

- 금액 표시는 원화·부가세 제외 기준이다. 재료 수량은 g·ml·개 등 재료 기준 단위를 함께 표시한다.
- 공란(미입력·해당 없음)과 숫자 0은 구별한다. 필수 값이 빠지면 0으로 대체하지 않는다.
- 판매 자료는 주문별 내역이 아니라 날짜·메뉴·채널별 집계다. 집계 행을 주문 수로 표현하지 않는다.
- 엑셀과 JSON은 같은 원천 자료의 두 형식이다. 동일한 자료를 두 번 반영하지 않으며, 중복 가져오기는 감지해 중단한다.
- 월 비용 계획과 날짜별 `월비용 일할 배분` 자료는 같은 비용을 서로 다른 단위로 표현한다. 두 금액을 실제 지출처럼 합산하지 않는다.
- 제공된 과거 판매 행의 단가·할인·순매출·수수료·개당 원가는 당시 기록값이다. 새 기록에 과거의 수수료율이나 원가를 무단 적용하지 않는다.
- 미마감 영업일과 미래 날짜의 미입력 판매는 0으로 간주하지 않는다. 자료의 마감 범위가 불완전하면 해당 기간이 부분 자료임을 표시한다. 현재 원천자료는 2025-07-01~2026-09-18 마감이며 9월 말까지 달력만 존재한다.
- 제공 샘플은 “가상 예시”임을 화면에서 구별한다. 예시 값으로 실제 저장·정산·발주가 완료된 것처럼 표현하지 않는다.
- 초기 메뉴·재료·레시피는 제공 샘플의 가상 기준자료로 준비한다. 파일 가져오기 기능을 사용한 것은 아니다.

## 4. 기능별 요구사항

각 기능은 요청한 순서대로 사용자가 하는 일과 입력, 프로그램 처리, 결과, 예외, 직접 확인 방법을 기술한다. “직접 확인”은 구현 완료 후 사람이 화면에서 수행할 수 있는 확인 절차다.

### 4.1 마감 홈 및 최종 마감 승인 — MVP

**사용자가 하는 일과 입력**

- 마감 홈에서 날짜 선택 버튼으로 영업일을 고른다.
- 탭/메뉴의 `마감 홈`, `당일 판매 기록`, `메뉴별 수익성`, `실제 손익·비용`, `재료 잔량 및 재고`로 이동한다.
- `판매 누락 추가`, `당일 지출 추가`, `재고 실사 조정` 등의 바로가기를 선택한다.
- 검토가 끝나면 `당일 영업 최종 마감 승인`을 선택하고 확인 팝업에서 승인한다.

**프로그램이 하는 일**

- 선택한 날짜의 판매 집계·실제 지출·재고 기록·마감 상태를 연결해 보여준다.
- 각 바로가기는 해당 입력 기능을 연다. 새 판매·비용·재고 기록은 저장 성공 후 관련 요약에 반영한다.
- 최종 승인은 해당 날짜를 완료 상태로 표시한다. 승인 뒤에도 정정은 허용하고, 승인 시각 및 이후 수정 사항을 변경 이력으로 남긴다.

**화면과 파일에 나오는 결과**

- 선택 기준일, 현재 마감 진행 상태, 판매·손익·재고 요약, 각 기능으로 이동하는 탭/버튼을 표시한다.
- 승인 뒤에는 완료 상태를 표시한다. 이 기능 자체는 파일을 만들지 않는다.
- 태블릿·모바일 등 반응형 화면 시안의 viewport 버튼은 시안 확인용 컨트롤로서 제품 데이터나 기기 설정을 변경하지 않는다.

**오류나 예외가 있을 때의 동작**

- 날짜가 없거나 자료가 없는 기간이면 빈 결과를 0으로 단정하지 않고 “기록 없음/자료 없음” 상태와 선택 기간을 보여준다.
- 아직 마감되지 않은 날은 미마감으로 표시하고 판매 0으로 간주하지 않는다.
- 필수 확인이 누락되었을 때 승인 여부를 임의로 추정하지 않는다. 승인 진행을 막고 미완료 항목을 안내한다. 필수 승인 항목은 마감 점검 규칙이 합의되기 전까지 미정으로 표시한다.
- 승인/저장 중 오류가 나면 완료 상태로 바꾸지 않고 재시도 안내를 표시한다.

**직접 확인할 방법**

1. 기준일을 바꾸고 요약의 날짜가 바뀌는지 확인한다.
2. 판매·비용·재고 바로가기를 각각 눌러 알맞은 기능이 열리는지 확인한다.
3. 저장하지 않은 필수 기록이 있을 때 승인 시 미완료 안내가 나오는지 확인한다.
4. 승인 후 완료 표시가 나고, 승인 이후 수정 시 변경 이력이 남는지 확인한다.

### 4.2 판매 기록 검색·필터·페이지 — MVP

**사용자가 하는 일과 입력**

- `메뉴명 또는 트랜잭션 번호 검색`에 검색어를 입력한다.
- 채널·분류·상태 선택 필터를 지정하거나 홀·포장·배달 등 채널 버튼을 선택한다.
- 체크박스로 행 또는 전체 행을 선택하고, `필터 초기화`와 페이지 이동을 사용한다.

**프로그램이 하는 일**

- 선택 조건에 맞는 판매 집계 행을 추려 목록에 표시한다.
- 목록의 건수와 합계는 현재 검색/필터 범위 기준임을 분명히 한다.
- 필터 초기화는 필터만 해제하며 원본 기록을 변경하지 않는다. 페이지 이동은 표시 행만 바꾼다.

**화면과 파일에 나오는 결과**

- 날짜·메뉴·채널·수량·단가·할인·순매출 등 판매 기록과 검색 결과 건수를 보여준다.
- 검색 결과가 없으면 빈 목록과 조건 수정 안내를 보여준다. 파일 출력은 이 기능에서 발생하지 않는다.

**오류나 예외가 있을 때의 동작**

- 검색어에 맞는 결과가 없으면 전체 자료가 삭제되거나 변경되지 않는다.
- 페이지 범위가 바뀌어 현재 페이지가 존재하지 않으면 유효한 첫 페이지로 이동한다.
- 검색·필터 실패 시 기존 저장 자료를 빈 값으로 덮어쓰지 않는다.

**직접 확인할 방법**

1. 메뉴명과 기록 번호 일부를 각각 검색해 해당 행만 남는지 확인한다.
2. 채널 필터를 바꾸고 결과/건수가 해당 채널에 한정되는지 확인한다.
3. 초기화를 눌러 모든 행이 다시 표시되는지, 페이지 버튼이 다음 행 묶음을 표시하는지 확인한다.

### 4.3 판매 기록 입력·수정·삭제 — MVP

**사용자가 하는 일과 입력**

- `판매 기록 수기 등록`, `신규 판매 기록 추가` 또는 홈의 `판매 누락 추가`를 누른다.
- 시안에 있는 날짜, 메뉴, 채널, 판매 수량, 판매 단가, 할인액, 결제 수단, 메모를 입력하거나 수정한다.
- 행의 수정/삭제 또는 다중 선택 후 `선택 항목 일괄 삭제`를 사용한다. 삭제 확인 팝업에서 취소하거나 확정한다.
- 저장 버튼을 눌러 반영한다.

**프로그램이 하는 일**

- 순매출은 **수량×단가−할인액**으로 계산한다. 총 판매액은 수량×단가다.
- 같은 날짜·메뉴·채널을 다시 입력하면 기존 집계에 합친다. 수량·총 판매액·할인액·순매출을 각각 합산하고, 표시용 단가는 합산한 총 판매액÷합산 수량인 가중 평균 단가로 나타낸다. 할인 정보와 매출 합계는 보존한다.
- 예: 기존 2잔×4,500원, 할인 500원과 추가 1잔×5,000원, 할인 0원 입력 시 가상 검산 결과는 수량 3잔, 총 판매액 14,000원, 할인 500원, 순매출 13,500원, 표시용 단가 약 4,667원이다.
- 새 저장은 판매 집계, 메뉴 수익성, 손익 및 재고 사용량에 반영한다. 과거 판매행의 당시 원가/수수료 스냅샷은 보존한다.
- 삭제/일괄 삭제는 확인 후 선택 행에만 적용한다. 취소는 자료를 바꾸지 않는다.

**화면과 파일에 나오는 결과**

- 저장 성공 시 목록의 집계와 관련 매출 요약을 갱신하고 저장 완료를 안내한다.
- 시안에는 `엑셀 다운로드`가 있다. 파일 내보내기는 수업 후 확장으로 분류하며, 활성화 시 현재 선택한 검색/필터 범위와 실제 데이터임을 파일명·내용에서 식별할 수 있어야 한다. 예시 화면의 가상 수치는 내보내지 않는다.
- 삭제 확인 팝업은 삭제 대상 건수/대상을 명시하고 취소·확정 선택을 제공한다.

**오류나 예외가 있을 때의 동작**

- 날짜·메뉴·채널·수량·단가 누락, 0 이하 수량/단가, 음수 할인, 할인액이 총 판매액보다 큰 경우 저장하지 않고 해당 입력을 알려준다.
- 날짜가 영업 달력에서 미마감/미래인 경우 판매 0을 자동 생성하지 않는다. 사용자가 명시적으로 입력한 판매만 기록하며 비영업일 판매 허용 정책은 미정으로 표시한다.
- 동일 집계 병합 중 단위/메뉴를 찾을 수 없거나 합계 계산을 완료할 수 없으면 기존 행을 보존하고 저장하지 않는다.
- 매출 총액·할인·순매출의 합계가 서로 맞지 않으면 저장 차단 및 수정 안내를 한다.
- 저장 실패 시 입력 내용을 지우지 않고 재시도 가능하게 한다.
- 삭제 팝업에서 취소/닫기를 선택하면 기존 데이터는 유지된다. 선택이 없거나 처리 오류가 나도 삭제하지 않는다.
- 결제 수단별 새 결제 수수료율은 자료에 정의되어 있지 않다. 과거의 수수료율을 새 판매에 자동 적용하지 않는다. 실제 수수료액이 제공되지 않으면 손익에서 미제공/미포함으로 표시한다.

**직접 확인할 방법**

1. 가상 테스트 값 2잔×4,500원과 500원 할인을 입력해 순매출 8,500원을 확인한다.
2. 같은 날짜·메뉴·채널에 1잔×5,000원을 더해 수량 3, 총액 14,000원, 할인 500원, 순매출 13,500원이 되는지 확인한다.
3. 할인액을 총액보다 크게 입력해 저장이 차단되는지 확인한다.
4. 한 행 삭제를 취소했을 때 데이터가 유지되고, 확정했을 때 선택 행만 삭제되는지 확인한다.
5. 저장 뒤 화면을 다시 열어 집계가 유지되는지 확인한다.

### 4.4 메뉴별 수익성 — MVP 조회; 시뮬레이션/내보내기 확장

**사용자가 하는 일과 입력**

- 기준일/기간을 선택하고 검색어, 메뉴 분류(전체·커피·논커피·베이커리·세트 등), 정렬 기준을 고른다.
- `메뉴별 수익성 분석` 표에서 메뉴별 수량, 매출, 원가, 제품 마진을 비교한다.
- 수업 후 확장으로 `레시피 원가표 내보내기` 또는 `신규 메뉴/레시피 시뮬레이션`을 사용한다.
- 시뮬레이션 팝업은 판매가, 식재료 원가, 포장재 포함 여부를 입력한다.

**프로그램이 하는 일**

- 시안에 명시된 제품 마진은 판매가에서 레시피 식재료 원가와 해당 채널의 포장 부자재 원가를 뺀 값이다. 임차료·정규 인건비·결제 수수료는 이 메뉴별 제품 마진에서 제외한다.
- 메뉴 마진율은 제품 마진÷판매가로 표시한다. 합의한 정의에 맞게 메뉴/채널/선택 기간별 집계를 비교한다.
- 식재료 원가는 레시피의 메뉴 1개당 기준량과 해당 적용 시점의 구매 가격·구매 용량을 기준으로 환산한다. 구매 가격은 한 팩 전체 가격이므로 한 팩 가격을 레시피 소량 사용량 원가로 그대로 쓰지 않는다.
- 채널별 레시피 적용 규칙을 따른다. 적용 채널이 빈 레시피 재료는 전체 채널에 적용하고, 포장 전용 재료는 포장 판매에만 적용한다.
- 메뉴를 검색하거나 분류·정렬을 바꾸면 표시 결과만 바뀐다. 시뮬레이션은 입력된 가상 판매가/원가/포장비만으로 예상 제품 마진을 갱신하며 실제 메뉴·실제 판매·저장 데이터는 바꾸지 않는다.
- 예: 가상 판매가 4,500원, 식재료 원가 1,300원, 포장 부자재 150원이면 제품 마진 3,050원, 마진율 약 67.8%다. 시안 예제 값이며 제공 자료의 실제 메뉴 수치라고 주장하지 않는다.

**화면과 파일에 나오는 결과**

- 검색·분류 결과 표, 판매량 기여/마진 비교, 채널별 제품 마진 및 기간 요약을 표시한다.
- 시뮬레이션 팝업은 입력값·가상 제품 마진·가상 마진율을 보여준다. `가상 시뮬레이션 적용`은 시안 문구대로 임시 비교에만 반영하고 공식 메뉴 원가·손익에 저장하지 않는다.
- 레시피 원가표 파일 내보내기는 수업 후 확장이다. 생성 시 선택 기간/메뉴, 원가 항목, 단위, 가상/실제 구분과 사용한 기준 시점을 명시한다.

**오류나 예외가 있을 때의 동작**

- 판매가가 0/음수이거나 원가가 음수·공란인 시뮬레이션은 결과 계산을 막고 입력 수정을 안내한다. 0원과 미입력은 구별한다.
- 필수 레시피 또는 재료 가격이 없는 메뉴는 마진을 0으로 대체하지 않고 “계산에 필요한 기준 정보 없음”으로 표시한다.
- 채널 적용 레시피가 중복되거나 단위가 맞지 않으면 해당 메뉴 결과를 계산 불가로 표시하고 원인을 안내한다.
- 일부 기간이 미마감이면 해당 기간의 마진 집계에 포함된 범위/마감 상태를 알린다.
- 파일 생성 실패 시 다운로드 완료로 표시하지 않고 다시 시도하게 한다.

**직접 확인할 방법**

1. 가상 메뉴의 판매가 4,500원, 식재료 1,300원, 포장재 150원을 대입해 3,050원·67.8%가 나오는지 확인한다.
2. 포장재 포함 여부를 전환해 포장 비용 차이가 계산에 반영되는지 확인한다.
3. 검색·분류·정렬을 바꾸어 표가 조건대로 바뀌고 저장 데이터는 바뀌지 않는지 확인한다.
4. 가상 시뮬레이션 적용 후 실제 판매/메뉴 기준값은 변경되지 않는지 확인한다.

### 4.5 실제 손익·비용 기록 — MVP 조회/비용 입력; 파일·예측 확장

**사용자가 하는 일과 입력**

- `일별 조회` 또는 `월별 누적`을 선택하고 기간 이동 버튼으로 조회일/월을 바꾼다.
- 비용 표에서 전체·변동·고정·인건/운영 등 분류를 선택한다.
- `비용 수기 등록` 또는 홈의 `당일 지출 추가`를 눌러 날짜, 비용 분류, 설명, 공급처, 금액, 메모 등 시안 필드를 입력한다. 기존 비용은 수정한다.
- `재검산 실행`으로 집계 갱신을 요청한다. 수업 후 확장 기능은 손익 엑셀 내보내기와 월간 예측 리포트다.

**프로그램이 하는 일**

- 판매 순매출과 메뉴 제조 원가를 분리해 표시한다. 비용 분류별 실제 비용을 선택 기간에 한 번만 반영한다.
- 사용자가 직접 입력한 실제 비용은 실제 손익에 반영한다. 월 비용 계획은 별도 비교 지표로만 표시하고 실제 비용 합계에 중복 더하지 않는다.
- 제공 샘플의 3,560개 `월비용 일할 배분` 행은 월 비용 계획을 날짜에 나눈 배분값이다. 이는 실제 영수증 기반 지출로 간주하지 않는다. 실제 기록과 계획 배분을 별도 유형으로 표시한다. 실제 지출 기록이 없는 과거 기간은 완전한 실제 손익으로 표시하지 않는다.
- 실제 운영이익은 순매출에서 판매로 소비된 레시피 원가(식재료·포장)와 확인된 실제 지출을 차감해 구한다. 결제 수수료액이 제공되지 않으면 수수료를 0으로 간주하지 않고 미제공/미포함 상태를 표시한다.
- 월 계획과 실제 지출의 비교는 같은 비용 항목·기간 기준으로 보여준다. 계획과 일별 배분액을 각각 실제 지출처럼 더하지 않는다.
- 예: 가상 순매출 10,000원, 식재료·포장 소비 원가 3,000원, 입력된 실제 비용 2,000원, 결제수수료 미제공이면 확인 가능한 손익 구성은 10,000−3,000−2,000=5,000원이며, 수수료 미포함 표시를 함께 한다. 이를 완전한 최종 손익이라고 표시하지 않는다.

**화면과 파일에 나오는 결과**

- 일/월 순매출, 원가, 실제 비용, 손익 구성과 비용 분류별 원장을 표시한다.
- 과거 월 계획 배분값, 실제 입력 지출, 계획 비교값은 구분된 표식/열로 표시한다.
- 비용 저장·수정 성공 시 목록·손익을 갱신한다. 삭제 기능은 시안에 명시되지 않아 현 FRD에서 새로 추가하지 않는다.
- 손익 엑셀 내보내기와 월말 예상 순이익/월간 예측은 수업 후 확장으로 둔다. 내보내기 시 실제·계획·배분값 구분 및 부분 기간 경고를 파일에도 기록한다.

**오류나 예외가 있을 때의 동작**

- 날짜·분류·설명·금액 등 시안에서 필수로 표시된 값이 빠지면 저장하지 않고 입력 위치를 안내한다.
- 금액은 양의 값만 허용한다. 0/음수, 숫자가 아닌 값은 저장을 막는다. 금액 범위는 부가세 제외 원화다.
- 이미 존재하는 실제 지출 행은 고유 기록으로 수정한다. 월 계획 배분행을 실제 지출행으로 덮어쓰지 않는다.
- 동일 기간의 월 계획과 일별 배분행이 같이 존재할 때 실제 지출 집계로 중복 계산하지 않는다.
- 자료에 실제 지출 또는 결제수수료액이 없으면 실제 손익을 완전한 수치로 꾸미지 않고 누락 구성요소를 알린다.
- 재검산 실패 시 직전 저장값을 지우거나 최신 계산처럼 표시하지 않는다.

**직접 확인할 방법**

1. 일별/월별 조회를 전환해 기간 합계가 바뀌는지 확인한다.
2. 가상 순매출 10,000원, 원가 3,000원, 실제 지출 2,000원을 넣어 확인 가능한 손익 5,000원과 미제공 수수료 안내를 확인한다.
3. 같은 월 비용의 계획값과 일할 배분 행을 함께 표시해도 실제 지출 합계에 두 번 포함되지 않는지 확인한다.
4. 필수 비용 항목을 비우거나 금액을 음수로 넣어 저장이 막히는지 확인한다.
5. 비용 저장 후 손익과 분류별 원장이 갱신되는지 확인한다.

### 4.6 재료 잔량·입고·폐기·실사 — 잔량/최소 기록 MVP; 발주 제안 확장

**사용자가 하는 일과 입력**

- 기준일과 전체/원두·유제품·포장재/주의 품목 필터를 선택한다.
- 재료 목록에서 `실사 조정` 또는 `입고 / 폐기 / 실사 기록`을 선택한다.
- 재료, 날짜, 변동 유형(입고/폐기/실사), 수량, 사유/메모를 입력한다. 실사 팝업은 기준 잔량과 실제 센 수량을 비교한다.
- 수업 후 확장 기능으로 재료 변동 이력, 발주 담기, 발주 데이터 내보내기/발송서 작성 기능을 사용한다.

**프로그램이 하는 일**

- 이론 잔량은 기초 재고 + 입고 − 폐기 − 판매 이론 사용량 ± 실사 조정으로 계산한다. 판매 이론 사용량은 각 판매 집계 수량에 해당 시점/버전 메뉴 레시피 사용량을 적용해 합한다.
- 실사 실제 수량이 기존 계산 잔량과 다르면 차이를 조정 이벤트로 남기고 잔량을 실사 수량에 맞춘다. 예: 이론 잔량 30개, 실사 27개면 −3개 조정 이벤트를 남기고 새 잔량은 27개다.
- 같은 재료 기준 단위(g/ml/개) 안에서 계산한다. 구매 포장 용량과 단위 환산을 구분한다. 구매 포장 전체 가격은 사용량 원가로 그대로 대입하지 않는다.
- 시안이 표시하는 이론 잔량, 실사 잔량, 안전재고 수준 및 부족 상태를 나눠 보여준다. 안전재고 일수는 영업일 기준이다.
- 수업 후 발주량은 추천 방식으로 일평균 사용량×(납기일+안전재고일)로 필요한 재고 수준을 추정하고 현재 잔량을 차감한다. 부족량을 구매 포장 단위/최소 주문 단위에 맞춰 올림한다. 계산에 필요한 소비량·납기·안전재고·구매 단위가 빠지면 발주량을 임의로 0으로 만들지 않고 계산 불가 이유를 표시한다.
- 예: 가상 기초 재고 40개 + 입고 20개 − 판매 사용 15개 − 폐기 2개 = 이론 잔량 43개. 실사 41개 입력 시 −2개 조정 후 기준 잔량은 41개다.

**화면과 파일에 나오는 결과**

- 재료별 기준 단위, 기초 재고, 입고·폐기, 판매 이론 소진량, 이론 잔량, 실사 잔량, 안전재고 및 상태를 표시한다.
- 입고/폐기/실사 저장 후 잔량 및 관련 부족 상태를 갱신한다. 실사 조정 기록에는 날짜·차이·사유를 남긴다.
- 수업 후 확장: 재고 이력 팝업, 발주 제안·공급처별 주문안, 발주 데이터 파일 다운로드. 시안 버튼에 표현된 “발송”은 사용자가 검토하고 내보내는 주문안 생성까지로 한정한다. 외부 공급사로 실제 전송하는 기능은 PRD에 없으므로 포함하지 않는다.

**오류나 예외가 있을 때의 동작**

- 재료·날짜·변동 유형·수량·사유 등 필수 항목이 없으면 저장하지 않는다.
- 입고·폐기 수량 입력은 0보다 커야 한다. 폐기 부호는 변동 유형이 결정하며 사용자가 음수를 직접 입력해 부호가 뒤집히지 않게 한다. 실사 수량은 0을 허용하되 음수는 거부한다.
- 재료 단위가 맞지 않거나 재료 기준 단위 변환을 확인할 수 없으면 잔량·원가 계산을 중단하고 사유를 알린다.
- 이론 잔량이 음수가 되면 0으로 잘라 감추지 않는다. 부족/기록 불일치 경고와 음수 값을 표시해 실사 또는 누락 입고를 확인하게 한다.
- 실사 조정 저장을 취소하거나 실패하면 원래 잔량을 유지한다. 같은 실사 입력을 다시 저장해 조정이 중복되지 않도록 기록 여부를 확인한다.
- 부정확한 레시피 버전/기준 가격이 없으면 이론 소진량·원가를 확정하지 않고 필요한 기준 정보를 표시한다.

**직접 확인할 방법**

1. 가상 40개 기초, 20개 입고, 판매 사용 15개, 2개 폐기로 잔량 43개를 확인한다.
2. 실사 41개를 입력해 −2개 조정 기록과 새 잔량 41개를 확인한다.
3. 잘못된 단위를 선택하거나 음수 실사 수량을 넣어 저장이 거부되는지 확인한다.
4. 이론 잔량보다 실제 판매 소진이 커지면 음수와 부족 경고가 표시되는지 확인한다.
5. 필터와 재료별 이력 화면에서 해당 재료의 입고·폐기·실사 기록만 표시되는지 확인한다.

### 4.7 엑셀 양식·파일 가져오기 및 내보내기 — 수업 후 확장

**사용자가 하는 일과 입력**

- 판매 기록 엑셀 양식을 내려받아 행을 채운다.
- 엑셀 또는 JSON 중 한 형식의 매장 자료를 선택해 가져오기를 요청한다. 한 원천 자료의 두 형식을 연달아 가져오지 않는다.
- 판매 기록, 레시피 원가표, 손익 보고서, 발주 참고 데이터 등의 내보내기를 요청한다.

**프로그램이 하는 일**

- 양식/가져오기 화면은 현재 디자인 시안에 없다. PRD 기능으로 남기며, 별도 화면 시안이 필요하다.
- 가져오기 전 파일 형식, 필수 열/필드, 날짜·수량·금액·기준 단위와 기존 자료 여부를 검사한다. 추천 오류 정책은 전체 검증 후 이상이 있으면 아무 행도 반영하지 않는 all-or-nothing 방식이다. 유효/오류 행 번호와 원인을 보여주고, 사용자가 수정 후 다시 올리게 한다.
- 이미 가져온 동일 원천 데이터는 중복으로 탐지해 반영하지 않는다. 엑셀과 JSON이 동일 자료임을 알아볼 수 있는 식별 정보가 없는 경우 재가져오기 판정 기준은 구현 전 확정이 필요하다.
- 내보내기는 사용자가 선택한 기간/필터와 일치하는 실제 데이터만 담는다. 공란과 0, 단위, 부가세 제외 금액, 자료 범위 및 가상 예시/실자료를 구분한다.

**화면과 파일에 나오는 결과**

- 성공 시 반영 건수와 가져온 범위를 확인할 수 있게 한다.
- 실패 시 파일명, 오류 행, 오류 필드, 원인과 조치 안내를 보여주고 기존 저장자료를 그대로 둔다.
- 내보내기 성공 시 다운로드 파일에 기간·통화·단위·실자료/가상 자료 구분을 포함한다.

**오류나 예외가 있을 때의 동작**

- 손상/미지원 파일, 필수 열 누락, 잘못된 날짜/단위/숫자, 중복 행, 기존 데이터와 식별 충돌이면 반영하지 않고 오류를 표시한다.
- 같은 원천 데이터로 확인되는 엑셀과 JSON 재가져오기는 중복 방지로 차단한다.
- 일부 행만 조용히 누락하거나 기존 자료를 자동 덮어쓰지 않는다.
- 파일 다운로드/생성 실패 시 성공으로 표시하지 않는다.

**직접 확인할 방법**

1. 양식 파일을 내려받아 열 이름/단위가 제공 자료의 의미와 맞는지 확인한다.
2. 정상 파일을 가져와 반영 건수와 조회 결과를 확인한다.
3. 필수 열 삭제, 잘못된 날짜, 지원하지 않는 파일, 중복 자료를 각각 넣어 아무 데이터도 반영되지 않고 행별 안내가 나오는지 확인한다.
4. 엑셀을 가져온 뒤 동등한 JSON을 다시 선택해 중복이 차단되는지 확인한다.
5. 기간을 필터링해 내보낸 파일의 기록과 화면 범위가 일치하는지 확인한다.

### 4.8 백업·복원 — 수업 후 확장

**사용자가 하는 일과 입력**

- 백업 파일 만들기를 선택한다.
- 복원할 백업 파일을 선택하고 미리보기 및 복원 확인 팝업에서 확정 또는 취소한다.

**프로그램이 하는 일**

- 백업은 당시 보존해야 할 매장 기록과 기준 정보를 한 파일로 저장하고 생성 시점을 알려준다.
- 복원 전 파일 구조·필수 자료·단위·버전을 검증하고 복원 대상 요약을 보여준다.
- 추천 복원 정책은 기존 데이터를 자동으로 합치거나 덮어쓰지 않고, 영향 범위를 확인 팝업에 보여준 뒤 사용자가 명시적으로 확정하도록 한다. 손상/오류 파일은 기존 자료를 보존한다.

**화면과 파일에 나오는 결과**

- 성공 시 백업 파일과 생성 날짜, 복원 성공 상태 및 복원된 기록 범위를 표시한다.
- 실패 시 원인과 기존 데이터가 변경되지 않았음을 표시한다.
- 백업 파일 형식·저장 위치·보존 암호화 규칙은 기술 구현 범위에서 별도로 결정하며 본 문서는 기술을 지정하지 않는다.

**오류나 예외가 있을 때의 동작**

- 손상/미지원/불완전한 백업, 필수 기준정보 불일치가 있으면 복원하지 않는다.
- 파일 검증이나 복원 중 오류가 발생해도 기존 기록을 부분적으로 덮어쓰지 않는다.
- 사용자가 확인을 취소하면 아무 자료도 변경하지 않는다.

**직접 확인할 방법**

1. 백업을 만들고 생성 시점 및 대상 기록 범위를 확인한다.
2. 테스트용 변경을 한 뒤 백업을 복원해 원래 자료가 복구되는지 확인한다.
3. 손상 파일과 다른 형식 파일, 취소 동작을 시험해 기존 자료가 유지되는지 확인한다.

## 6. 화면 시안 대비 미정/설계 필요 항목

- **가져오기와 백업/복원 화면:** PRD 필수/확장 기능에 있으나 제공 시안에 버튼·입력 폼이 없다. 이 기능의 별도 화면 시안이 필요하다.
- **결제수수료 산정:** 과거 행에는 수수료액이 있으나 새 입력의 결제 수단별 수수료율/정산값은 주어지지 않는다. 자동 수수료율을 임의로 만들지 않으며 수수료액이 없으면 실제 손익의 미포함 상태를 보여준다.
- **실제 지출 입력과 월 비용 계획의 매핑:** 과거의 월 계획/일할 배분과 사용자가 새로 입력하는 실제 지출을 비교할 때 비용 항목·월 기준 매칭 방식은 별도 확정이 필요하다. 본 FRD는 실제 지출을 계획 배분과 분리하는 원칙까지만 정했다.
- **마감 승인 필수 체크 항목:** 승인 시 어떤 판매/비용/재고 확인을 필수로 강제할지는 시안에 명시되지 않았다. 승인 후 수정 허용과 변경 이력 기록만 정했다.
- **판매 날짜 정책:** 비영업일/과거 마감일 판매 입력, 부분 마감일 집계 허용 기준은 자료/시안에 명확하지 않다. 미마감·미래 날짜를 판매 0으로 보지 않는 기준은 적용한다.
- **요리법/단위 가격 시점:** 판매에 적용할 레시피 버전 및 가격 이력이 없거나 여러 버전이 겹칠 때의 원가 선택 규칙은 데이터에 없는 정책을 만들어내지 않도록 기준정보 오류로 표시한다.
- **손익 완전성:** 과거 예시 자료의 비용 행은 월 비용 계획을 일할 배분한 값이며 신규 실제 지출/결제 수수료 실측값과 같지 않다. 이 데이터만으로 실제 손익을 완전하다고 주장할 수 없다.

## 7. 검사 완료 기준

- 판매 순매출 및 동일 집계 병합 계산이 5절의 예시와 일치한다.
- 메뉴 제품 마진에 식재료·채널 포장 원가가 반영되고, 임차료·정규 인건비·결제 수수료는 메뉴 마진에서 제외된다.
- 실제 손익에서 실제 지출과 계획 배분/월 비용 계획이 구별되고 같은 비용이 중복 합산되지 않는다.
- 재료 잔량은 입고·폐기·레시피 판매 소진·실사 조정을 올바르게 반영하며, 실사 차이와 기록이 보존된다.
- 필수값 누락, 숫자 범위 오류, 잘못된 단위, 중복 판매 입력, 삭제 취소, 저장/재검산 오류에서 기존 정상 데이터가 손실되지 않는다.
- 기록 저장 후 화면을 다시 열어도 변경 결과가 유지된다.
- 자료가 미마감이거나 값이 미제공이면 0으로 둔갑하지 않고 누락/부분 자료로 표시된다.
- 실제/가상 데이터, 과거 스냅샷, 계획 배분, 실제 지출, 부분 기간의 구분이 화면과 내보낸 파일에 일치한다.
- 시안에 있으나 수업 후 확장인 버튼/기능은 MVP 테스트 완료로 잘못 보고하지 않는다.
