# 프렙 카페 운영 관리 웹 프로그램 개발 계획

> 이 계획은 `docs/01_PRD.md`, `docs/02_FRD.md`, `docs/03_TRD.md`와 `디자인/` 시안을 기준으로 한다. 예상 시간은 AI 보조 구현 및 사용자 확인을 포함한 실습 추정치이며 보장 시간이 아니다. **아직 구현은 시작하지 않았다.**

## 전체 작업 순서와 나눈 이유

1. **저장·접근 기반 → 판매·메뉴 수익성 → 실제 손익·재고·마감** 순으로 진행한다. 로그인과 데이터 구조가 먼저 있어야 모든 기록을 안전하게 저장할 수 있고, 메뉴·레시피 기준자료가 준비되어야 판매 및 원가 계산을 검증할 수 있다. 판매 집계가 안정된 뒤 비용과 재고를 연결해야 핵심 흐름을 끝까지 확인할 수 있다.
2. 각 EPIC(서로 의존하는 기능의 작업 묶음)이 끝날 때마다 실제 화면에서 사용할 수 있는 결과를 확인한다. 다음 EPIC 시작 시 앞 EPIC의 계산·저장·오류 검증을 회귀 검사로 다시 실행한다. 회귀 검사는 새 작업이 기존 기능을 망가뜨리지 않았는지 재확인하는 검사다.
3. PRD/FRD에서 정한 기능과 계산을 빼지 않는다. 시간 절약은 복잡한 차트·시각 효과·픽셀 단위 시안 재현을 줄이는 데서 한다. 결과는 요약 카드와 표 중심으로 보이고 PC·태블릿·모바일에서는 기본 반응형 사용성을 유지한다.
4. 수업 후 확장 기능은 별도 목록으로 두며 이번 Story 완료 조건에 포함하지 않는다.

### 문서 차이와 선행 결정

- PRD는 비용 기록 삭제를 필수로 하지만 FRD의 비용 화면은 삭제를 범위에서 빼 두었다. 개발 계획은 기능을 빠뜨리지 않도록 PRD 기준으로 최소 삭제 확인 팝업을 포함한다.
- FRD는 마감 승인 전 필수 확인이 빠지면 승인을 막으라고 하지만, 어떤 항목을 필수로 볼지는 아직 목록이 없다. 20분 작업 준비에서 판매·비용·재고 각각의 확인 상태와 “자료 없음” 처리 기준을 확정한 뒤 Story 9의 완료 조건에 반영한다. 공란은 0으로 보지 않는다. 이 결정 전에는 마감 승인을 완료 처리하지 않는다.
- 디자인의 복잡한 그래프 표현은 승인된 범위 축소안에 따라 표·요약 카드로 단순화한다. 수익성/손익 숫자나 핵심 데이터 기능은 줄이지 않는다.

### 전체 일정

| 구간 | 작업 | 예상 시간 |
|---|---|---:|
| 계획 확정·작업 준비 | 기능 범위와 검증 예시 확인, 개발·Preview·운영 환경 구분 | 20분 |
| 화면 설계 조정 | 시안의 핵심 마감 흐름을 단순한 카드·표·입력 폼으로 정리 | 30분 |
| EPIC 구현 및 사용자 확인 | 아래 9개 Story의 구현, 자동 검사, 사용자의 화면 확인 | **100분** |
| 통합·회귀 검사 | 처음부터 끝까지 전체 흐름, 입력 오류, 저장 유지, 세 화면 폭 확인 | 60분 |
| 배포·운영 확인 | GitHub 변경 검토, Vercel Preview 검토, 운영 배포와 기본 접근 확인 | 30분 |
| **총 실습 시간** |  | **240분(4시간)** |

EPIC 구현 시간 100분은 MVP의 단순 UI와 기존 추천 기술 구성을 전제로 한 낙관적 추정이다. 실제 구현 중 위험이 드러나도 계산 정확성·저장·기본 오류 처리·검사를 생략하지 않는다. 100분에 맞추기 어렵다면 남은 기능과 영향 및 필요한 추가 시간을 먼저 사용자에게 제시하고, 임의로 미완료 처리하지 않는다.

## EPIC·Story 총개수와 예상 시간

- **EPIC 3개, User Story 9개**다. Epic당 최대 5개, 전체 권장 6~9개 제한을 지킨다.
- EPIC별 구현·사용자 확인 시간은 **20분 + 35분 + 45분 = 100분**으로 추정한다.
- 각 Story 시간에 해당 기능의 자동 검사와 사용자의 화면 확인을 포함한다.

## EPIC 1. 안전한 사용 및 가상 기준자료 기반

**예상 시간: 20분 (Story 2개)**

**현재 상태: 진행 중 — 사용자 화면 확인과 실제 Supabase 인증·DB 검사 전이므로 미완료.**

**완료 기준**

- 점주 인증이 된 경우에만 업무 화면과 매장 자료에 접근한다.
- 제공 샘플 기준자료가 가상 예시로 구분되어 준비되고, 데이터베이스에 저장된 자료를 새로고침/재로그인 후에도 읽는다.
- 로그아웃 상태와 허용되지 않은 계정은 업무 데이터에 접근할 수 없다.
- 화면 결과: 로그인 가능한 마감 앱과 메뉴·재료 기준자료가 표시되는 기본 마감 홈.

### Story 1. 점주로 로그인하고 매장 화면을 안전하게 연다 — 10분

**사용자가 할 수 있는 일**

- 등록된 점주 이메일로 일회용 코드를 요청해 로그인하고 로그아웃한다.
- 로그인 뒤 마감 홈으로 이동한다.

**자동 검사**

- 로그인 전 업무 경로 요청이 거부되는지 검사한다.
- 등록 이메일 코드 성공, 잘못된/만료된 코드 거부, 로그아웃 뒤 세션 만료를 확인한다.
- 코드·세션 토큰·비밀번호가 로그/화면에 노출되지 않는지 검사한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 등록 이메일을 입력하고 받은 코드를 넣는다. 마감 홈이 열린다.
2. 로그아웃한 뒤 브라우저에서 업무 화면을 다시 연다. 로그인 화면으로 안내되고 판매·비용·재고 값은 보이지 않는다.

### Story 2. 가상 예시 기준자료를 보고 저장된 기준자료를 다시 읽는다 — 10분

**사용자가 할 수 있는 일**

- 마감 홈에서 메뉴·재료 기준자료가 준비된 상태를 확인한다.
- “가상 예시 데이터” 표식을 확인한다.

**자동 검사**

- 시드 자료(초기 준비 데이터) 적용이 반복되어도 자료가 중복 생성되지 않는지 확인한다.
- 메뉴 8종, 재료 11종, 레시피 22건 및 연결된 재료·메뉴 ID가 정상인지 확인한다.
- 앱이 동일 샘플을 엑셀과 JSON 양쪽에서 중복 가져오지 않는지 검사한다. 이번 범위에서 파일 가져오기 기능은 실행하지 않는다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 마감 홈에서 메뉴·재료 보기로 이동한다. 가상 예시 표식과 준비된 목록이 나타난다.
2. 새로고침 후 목록이 남아 있고 항목이 중복되지 않는다.

## EPIC 2. 판매를 기록하고 메뉴 제품 수익성을 확인한다

**예상 시간: 35분 (Story 2개)**

**완료 기준**

- 날짜·메뉴·채널별 판매 집계를 입력·수정·삭제하고, 같은 날짜·메뉴·채널의 입력은 합의된 규칙대로 병합한다.
- 순매출 계산, 기본 입력 검증, 잘못된 저장 방지와 새로고침 후 보존이 확인된다.
- 제품 마진은 FRD 정의(판매가 − 식재료 원가 − 적용 포장 원가)와 일치하며 결제수수료·임차료·정규 인건비는 제품 마진에 섞이지 않는다.
- 화면 결과: 판매 목록과 메뉴/채널별 마진을 조회한다.

### Story 3. 당일 판매 집계를 입력·수정·삭제한다 — 22분

**사용자가 할 수 있는 일**

- 날짜, 메뉴, 판매 채널, 수량, 단가, 할인액, 결제 수단, 메모를 입력한다.
- 저장된 판매를 검색·필터링하고 수정하거나 삭제한다.
- 같은 날짜·메뉴·채널 집계를 다시 입력해 기존 집계에 합친다.

**자동 검사**

- 판매 계산 단위 검사: 수량×단가−할인액.
- 합산·병합 검사: 수량, 총 판매액, 할인, 순매출 합산 후 표시용 단가를 가중 평균으로 계산한다.
- 필수값, 수량/단가 0 이하, 음수 할인, 할인 초과, 누락 메뉴·채널, 중복 저장, 저장 실패를 검사한다.
- 저장 뒤 새 조회에서 값이 남는지, 삭제 취소가 자료를 바꾸지 않는지 확인한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 가상 입력 2잔×4,500원, 할인 500원을 저장한다. 총 판매액 9,000원과 순매출 8,500원이 표시된다.
2. 같은 날짜·메뉴·채널로 1잔×5,000원, 할인 0원을 추가한다. 한 집계가 수량 3, 총액 14,000원, 할인 500원, 순매출 13,500원, 표시 단가 약 4,667원이 된다.
3. 새로고침 후 같은 집계가 남는다. 편집 후에도 유지된다.
4. 할인액을 총액보다 크게 해 저장한다. 오류가 안내되고 기존 값은 그대로다.
5. 삭제 확인 팝업에서 취소하면 유지되고, 확정하면 선택 집계만 삭제된다.

### Story 4. 메뉴별 제품 마진을 확인한다 — 13분

**사용자가 할 수 있는 일**

- 기준일/기간과 메뉴 분류·채널을 선택해 메뉴 수익성 목록을 조회한다.
- 메뉴별 판매 수량·식재료 원가·적용 포장 원가·제품 마진을 확인한다.

**자동 검사**

- 레시피 사용량과 구매 포장 단위/가격을 기준 단위로 환산하는 계산 단위 검사.
- 제품 마진 및 마진율의 수치 예시 검사.
- 결제수수료·임차료·정규 인건비가 메뉴 제품 마진에 포함되지 않는지 확인한다.
- 필수 레시피/가격 누락 시 0으로 대체하지 않고 계산 불가로 처리하는지 검사한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 가상 판매가 4,500원, 식재료 원가 1,300원, 포장 원가 150원인 메뉴를 조회한다. 제품 마진 3,050원, 마진율 약 67.8%가 표시된다.
2. 메뉴/채널을 바꾸면 맞는 결과가 나오고, 결제수수료·고정비는 이 제품 마진에 포함되지 않는다.
3. 새로고침 후 판매 목록과 메뉴 마진이 유지된다. 자료가 빠진 메뉴는 0원이 아니라 기준 정보 누락 상태다.

## EPIC 3. 실제 손익·재고를 확인하고 마감을 완료한다

**예상 시간: 45분 (Story 5개)**

**완료 기준**

- 실제 지출은 입력·수정·삭제되고, 월 비용 계획 및 과거 `월비용 일할 배분`과 구별된다.
- 일별·월별 손익에서 실제 입력값만 실제 지출로 반영되고 중복이 없다. 누락 수수료와 불완전 자료는 표시된다.
- 입고·폐기·실사 기록이 보존되고 재료 잔량과 실사 조정 계산이 일치한다.
- 마감 홈에 저장된 판매·손익·재고 상태가 연결되고, 마감 승인과 이후 변경 이력을 확인한다.
- EPIC 1·2의 자동 검사와 수동 핵심 확인을 다시 실행해 회귀가 없음을 확인한다.
- 화면 결과: 사용자가 판매 입력 → 메뉴 마진 → 실제 손익 → 재료 잔량 → 마감 완료 표시까지 이어서 수행할 수 있다.

### Story 5. 실제 비용을 입력·수정·삭제한다 — 8분

**사용자가 할 수 있는 일**

- 날짜·비용 분류·설명·공급처·금액·메모를 입력하거나 저장된 실제 지출을 수정·삭제한다.
- 실제 지출과 월 비용 계획/계획 일할배분 항목을 구분한다.

**자동 검사**

- 필수값과 양의 금액 검증, 실제 지출과 계획 배분 자료의 종류 분리 검사를 한다.
- 생성·수정·삭제 및 삭제 취소 후 재조회/새로고침 시 상태가 일치하는지 확인한다.
- 같은 월 계획 금액과 일할배분 자료가 실제 지출로 이중 계산되지 않는지 검사한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 가상 실제 비용 2,000원을 입력한다. 실제 비용 목록에 나타나고 계획 배분 행과 다른 표시를 갖는다.
2. 새로고침 후 기록이 남고 금액 수정이 저장된다.
3. 삭제 취소 시 유지되고 삭제 확정 시 실제 지출만 삭제된다.
4. 금액을 비우거나 음수로 저장한다. 저장이 막히고 기존 행은 유지된다.

**문서 차이 처리:** PRD는 비용 기록의 입력·수정·삭제를 필수로 요구하지만 FRD는 시안에 삭제 버튼이 없다는 이유로 새 삭제 기능을 제외했다. 개발 계획은 상위 요구인 PRD를 보존해 **최소 삭제 확인 팝업**을 포함한다. 이는 새로운 업무 기능 추가가 아니라 빠진 필수 조작을 화면에 반영하는 것이다.

### Story 6. 일별·월별 실제 손익을 확인한다 — 10분

**사용자가 할 수 있는 일**

- 일별과 월별 누적을 전환하고 기간을 이동한다.
- 순매출·소비 원가·실제 지출·계획 비교를 확인한다.

**자동 검사**

- 손익 산식 검사와 월/일 기간 집계 검사를 한다.
- 실제 비용과 계획/일할배분 비용이 중복되지 않는지 검사한다.
- 수수료 미제공, 실제 지출 미입력, 미마감/부분 연간 기간을 0/완전 손익으로 잘못 표시하지 않는지 확인한다.
- EPIC 2 판매 데이터 수정이 손익 집계에 바로 반영되는지 회귀 확인한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 가상 순매출 10,000원, 소비 원가 3,000원, 실제 지출 2,000원을 본다. 확인 가능한 손익은 5,000원이고 수수료 미제공 표시가 있다.
2. 일별/월별로 바꾸면 날짜별 값과 기간 합계가 맞는다.
3. 과거 월 계획 일할배분값은 실제 지출과 분리 표시되고, 월 비용 계획과 더해져 중복되지 않는다.
4. 새로고침 뒤 판매·실제 지출·손익이 유지된다.

### Story 7. 재료 입고와 폐기를 기록한다 — 8분

**사용자가 할 수 있는 일**

- 날짜·재료·입고/폐기 유형·수량·사유를 입력한다.
- 저장된 입고/폐기 기록을 확인한다.

**자동 검사**

- 수량은 양수로 받고 이벤트 유형에 따라 증가/감소 방향이 맞는지 확인한다.
- 재료 기준 단위(g/ml/개), 재료 ID, 날짜, 필수 사유를 검증한다.
- 이벤트 저장과 목록 재조회/새로고침 보존, 중복 제출 방지를 확인한다.
- 입고/폐기 기록이 EPIC 3 Story 8의 잔량 계산에 연결되는지 검사한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 가상 입고 20개를 기록한다. 해당 재료의 입고 이력과 잔량이 20개 증가한다.
2. 폐기 2개를 기록한다. 잔량은 2개 감소한다.
3. 새로고침 뒤 두 변동과 사유가 남고, 음수 입력/잘못된 단위는 거부된다.

### Story 8. 재료 잔량을 계산하고 실사 차이를 조정한다 — 9분

**사용자가 할 수 있는 일**

- 재료별 이론 잔량과 안전재고 상태를 확인한다.
- 실제 재고 수량을 입력해 계산 잔량과 맞추고 조정 사유를 남긴다.

**자동 검사**

- 기초 재고 + 입고 − 폐기 − 판매 이론 소진량 ± 실사 조정 계산을 확인한다.
- 단위 불일치, 레시피 누락, 음수 이론 잔량 처리와 중복 실사 제출을 검사한다.
- 실사 이벤트 저장 후 새 조회/새로고침에서 잔량이 유지되는지 검사한다.
- EPIC 2의 판매 변경이 재료 이론 소진 및 잔량으로 이어지는지 회귀 확인한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. 가상 기초 40개, 입고 20개, 판매 사용 15개, 폐기 2개를 확인한다. 실사 전 잔량은 43개다.
2. 실제 수량 41개를 기록한다. 차이 −2개가 조정 이력에 남고 이후 기준 잔량은 41개다.
3. 새로고침 뒤 이론/실사 수량과 조정 사유가 남는다. 단위 오류는 저장되지 않고 음수 잔량은 0으로 숨지 않고 경고로 표시된다.

### Story 9. 마감 홈에서 하루를 검토하고 마감 완료를 표시한다 — 10분

**사용자가 할 수 있는 일**

- 마감 기준일, 판매·손익·재고 요약과 자료 누락/미마감 안내를 확인한다.
- 판매·비용·재고 바로가기로 이동해 검토를 완료한다.
- `최종 마감 승인` 확인 팝업에서 승인을 한다. 승인 후에도 정정은 가능하다.

**자동 검사**

- 판매·메뉴마진·실제 손익·재고가 같은 기준일/기간으로 연결되는 통합 검사를 한다.
- 승인 상태 저장, 새로고침 유지, 승인 뒤 수정 이력 기록을 확인한다.
- 로그아웃 상태의 읽기/쓰기 거부와 사용자별 응답 분리를 확인한다.
- 판매 입력 → 수익성 → 손익 → 재고 → 마감 완료까지 E2E(End-to-End, 사용자 흐름 전체를 이어 검사) 시나리오를 실행한다.

**내가 화면에서 확인할 행동과 예상 결과**

1. EPIC 2~3의 예시 기록을 한 날짜로 확인한다. 마감 홈 요약과 각 상세 화면의 판매/손익/잔량이 같은 값이다.
2. 자료가 없거나 미마감인 항목은 0으로 나타나지 않고 상태 안내로 표시된다. 필수 미완료가 있으면 FRD 기준대로 승인이 막히고 빠진 항목이 표시된다.
3. 확인 후 승인하면 마감 완료 표시가 나온다. 판매 기록을 정정하면 수정 결과가 저장되고 변경 이력이 남는다.
4. 승인 이후 새로고침해도 완료 상태와 기록이 유지된다.
5. PC·태블릿·모바일 너비에서 표/입력/팝업을 사용할 수 있다. 복잡한 차트 대신 표/요약 카드가 보이는 것은 승인된 시각적 범위 축소다.

| 시점 | 다시 확인할 이전 기능 | 다음 단계로 넘어가기 위한 조건 |
|---|---|---|
